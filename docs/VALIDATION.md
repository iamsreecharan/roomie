# Validation record

The rooms-and-friends iteration was tested in the cloud development machine on October 9, 2026. Render's live service was not accessed or independently verified during this iteration.

- **28 API/Socket.IO integration tests passed**, with no skips. Coverage includes authentication, consent, accepted friendship, default-off directed knock permission, request rejection/cancellation, message bounds, five-person rooms, voluntary admission, guest permissions, private-resource grants, private uploaded photos, blocks/unfriend/leave revocation, ephemeral chat, call signaling, optimistic scene versions, and upload validation.
- Persistence checks verify friendships, knock permissions, and customized rooms survive restart. Existing follows do not become friendships. Only the exact untouched original starter layout migrates to a bed-only room; customized layouts remain intact.
- Legacy posts remain owner-only, including media declared public before this update. Legacy Hall publication cannot expose uploaded photos outside the owner/approved-resource boundary.
- Uploaded images now load from the default hidden `.data/media` directory after explicit authorization. A regression test checks private media in a hidden storage directory; the browser test verifies an admitted guest's approved photo actually decodes.
- The desktop and **390 px mobile** browser suite passed with no unexpected JavaScript errors or horizontal overflow. It exercises email login/logout, Roomie preview/apply, top username suggestions, friend requests and knock approval, short knock messages, explicit joining, friend invite suggestions, two/three visible room avatars, overlay chat and closing it, sharing rejection/approval, photo viewing, host removal, guest departure, avatar expression/outfit persistence, and browser navigation.
- A deliberately malformed room response produces a visible recovery screen while navigation remains available. Returning to the room fetches clean data and recovers without a full browser refresh. The reported intermittent blank page was not reproduced in the tested normal navigation flows.
- A concurrent load run created **50 accounts, 50 authenticated sockets, and ten five-person rooms**. **610 measured requests** completed with **zero errors**, p50 **155 ms**, p95 **262 ms**, and maximum **379 ms**. The runner deleted all 50 temporary accounts.
- The production client build passed. An isolated production startup served compiled assets, passed health checks, disabled demo access, required authentication, and issued Secure/HttpOnly/SameSite cookies. The single-instance Render configuration and persistent database/media paths remain unchanged.

These local results measure the tested API, realtime notification, room, and browser workloads. They do not establish public-network video capacity. Call signaling and permission cleanup are covered here; actual RTP media transfer was verified in the preceding version with fake devices and a local TURN TCP relay, and was not repeated for this interface iteration.

Google OAuth and OpenAI provider requests require configured live credentials and were not independently exercised against live accounts/keys here. See [FEATURES.md](FEATURES.md) and [RENDER.md](RENDER.md) for deployment details.

The join and mobile editing follow-up passed the production build, all 28 API/Socket.IO tests, and the desktop/mobile browser suite. The browser checks verify that an accepted knock opens a join prompt without leaving the current profile, dismissal survives refresh while the top Join button remains available, and accepted invitations use the same prompt. On a 390 px mobile viewport, furniture was dragged and saved with the save control already visible above navigation, and the saved coordinates were verified through the API. Render live deployment was not checked in this follow-up.
